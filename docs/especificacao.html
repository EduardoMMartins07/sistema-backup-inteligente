01 Visão Geral

Propósito, escopo e objetivos do sistema

O Smart Backup é uma aplicação desktop desenvolvida em Python para monitoramento contínuo de diretórios, classificação inteligente de arquivos e backup incremental com deduplicação por hash, snapshots JSON e criptografia em envelope.

O sistema combina monitoramento em tempo real (watchdog), análise de metadados via árvore de decisão local com integração opcional à Gemini API (Google), e armazenamento incremental com restauração por manifesto. A interface gráfica em Tkinter oferece controle completo sobre backups, agendamento, histórico e restauração.

04 Arquitetura e Fluxo

Como os componentes se integram e o fluxo de execução

4.1 Inicialização

  1. Garante pastas necessárias (config/, dataset/, ml/)
  2. Detecta se é primeira execução (config sem diretórios OU nenhum usuário)
  3. Inicia monitoramento em thread separada (daemon)
  4. Inicia agendador em thread separada (daemon)
  5. Abre tela de login/painel na thread principal do Tkinter
  6. Após fechar o painel, inicia o ícone da bandeja

4.2 Fluxo Geral

Login → Painel Principal
│
├─ Backup Manual → Scanner → Backup Incremental
├─ Backup Agendado → Scanner → Backup Incremental
└─ Monitoramento → Dispara Scanner → Dataset Atualizado

4.3 Fluxo de Backup Incremental

Iniciar Backup → Scanner → Dataset CSV → Classificação
↓
Backup Incremental → Objetos por hash → Snapshot JSON → Histórico → ZIP criptografado

05 Funcionalidades Detalhadas

Descrição completa de cada funcionalidade implementada

5.1 Autenticação e Controle de Acesso auth/

Sistema de Usuários

  • Armazenamento: config/users.json com senhas hasheadas via PBKDF2-SHA256 (260.000 iterações)
  • Campos: username, name, role, password (hash + salt), company_id, metadados criptográficos
  • Operações: criar, autenticar, listar, atualizar, deletar, alterar senha
  • Recuperação: chave única formato RECOVERY-XXXX-XXXX-XXXX-XXXX
  • Autenticação: PBKDF2 + HMAC compare_digest + descriptografia da chave mestra

Sistema de Permissões (RBAC)

5.2 Monitoramento em Tempo Real monitor/

  • Usa watchdog.Observer para monitorar diretórios configurados
  • Eventos capturados: criação, modificação, remoção e movimentação de arquivos
  • Cooldown: 2 segundos entre varreduras para evitar disparos excessivos
  • Ignora caminhos internos: config/, dataset/, .git/, __pycache__/
  • Dispara run_scanner() automaticamente ao detectar mudanças

5.3 Scanner e Dataset scanner/

  • Varre todos os diretórios configurados recursivamente
  • Para cada arquivo coleta: nome, extensão, tipo, tamanho, datas, hash SHA-256, contadores de atividade, contexto do diretório
  • Anota arquivos duplicados por hash
  • Aplica classificação (regras + LLM opcional)
  • Gera/atualiza dataset/files_dataset.csv via pandas

Árvore de Decisão Local

Critério Impacto Motivo
Modificações frequentes (≥2 ou ≤2 dias) +18 Arquivo modificado recentemente
Extensão de alto valor +18 Extensão com valor para backup
Extensão de sistema/programa +20 Relevante para sistema
Acessos frequentes (≥2) +14 Arquivo acessado várias vezes

Palavra-chave (scanner) +10 Keyword detectada

Extensão de baixo valor -18 Temporário/descartável
Contexto de baixo valor -35 Cache, venv, temp

Limiares: ≥70 → alta, ≥40 → média, <40 → baixa

Integração Gemini API (opcional)

  • Ativada via GEMINI_API_KEY (variável de ambiente ou .env)
  • Envia apenas metadados — nunca o conteúdo do arquivo
  • Prompt estruturado pedindo classificação JSON
  • Cache local (até 1000 entradas) para evitar chamadas repetidas
  • Fallback automático para regras locais se API falhar
  • Modelo padrão: gemini-2.5-flash
  • Mescla resultado da LLM com regras locais (prioridade mais alta vence)

5.5 Backup Incremental com Deduplicação backup/

Estrutura de Armazenamento

📁 backups/<usuario>/
├── index.json
└── 📁 YYYY-MM-DD/
├── 📁 arquivos_relacionados/
└── <hash_sha256>
└── 📁 snapshots/
└── snapshot_2026-05-12_08-00-00.json

Mecanismo de Deduplicação

  • Cada arquivo é armazenado uma única vez, identificado por hash SHA-256
  • Se o hash já existe, apenas uma referência é criada
  • O index.json mantém contagem de referências para cada objeto

Status dos Arquivos

Status Significado
stored_new_object Novo objeto armazenado
referenced_existing_object Hash já existente, apenas referência
skipped_unchanged Arquivo não modificado desde último backup
skipped_not_eligible Não elegível pela política de prioridade
error Falha ao processar

Política de Backup por Prioridade

Prioridade Produção DEV MODE
baixa A cada 7 dias A cada 30 min
média A cada 2 dias A cada 15 min
alta Início do dia + a cada 4h A cada 5 min

Verificação a cada 10 min (produção) ou 1 min (DEV MODE). Estado persistente em config/priority_backup_state.json.

Agendamento

  • Thread separada com loop a cada 20s
  • Verifica se há backup agendado pendente via janela de horário
  • Processa backup por prioridade se habilitado
  • Suporta horário de início e fim para agendamento diário

5.6 Criptografia security/

Esquema de Criptografia em Envelope

Senha do Usuário
└─▶ PBKDF2-SHA256 (390.000 iterações + salt) → Chave de Senha
└─▶ AES-256-GCM wrap → Chave Mestra (por usuário)
└─▶ AES-256-GCM wrap → Chave de Backup (por execução)
└─▶ AES-256-GCM encrypt → Arquivo de Backup (.zip.enc ou objeto)
  • Algoritmo: AES-256-GCM com nonces únicos de 12 bytes
  • KDF: PBKDF2-SHA256 com salt de 16 bytes
  • Tag de autenticação: embutida no ciphertext
  • Troca de senha: apenas a chave mestra é recriptografada; backups intactos
  • Redefinição sem senha antiga: gera nova chave mestra → perde acesso a backups antigos

5.7 Restauração backup/

  • Restaura arquivos de snapshots incrementais
  • Suporta estratégias de conflito: renomear ou pular
  • Preserva datas de modificação originais
  • Exporta snapshot completo para ZIP
  • Busca por nome de arquivo na interface

07 Instalação e Execução

Pré-requisitos e passos para execução

Pré-requisitos

  • Python 3.13 ou superior
  • pip
  • Ambiente Windows recomendado
  • Chave GEMINI_API_KEY opcional para classificação com Gemini

Passos

# 1. Criar ambiente virtual
python -m venv venv
venv\Scripts\activate

# 2. Instalar dependências
pip install -r requirements.txt

# 3. (Opcional) Configurar chave Gemini
$env:GEMINI_API_KEY = "sua-chave-aqui"

# 4. Executar
python main.py
